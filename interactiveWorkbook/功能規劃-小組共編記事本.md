# InteractiveWorkBook｜小組共編記事本

規劃日期：2026-10-12。狀態：已完成第一版實作與本機驗證，尚未部署。本文保留產品規劃脈絡；實際資料契約及差異見「架構與模組規約.md」的記事本章節。

## 1. 目的與建議範圍

讓同組學員在討論時，同時記錄想法、共識、待確認事項，再由答案編輯者整理成正式作答。

採「每個小組、每堂課共用一本記事本」，以段落為單位指定所屬題目或「全局」。記事本上方可篩選題目；篩選特定題目時新增的段落自動歸屬該題，已存在的段落也可改到其他題目或全局。以上為使用者已指定需求；下述全部／全局的篩選語意、段落操作細節與例外處理為建議預設。切換篩選只改變顯示範圍，不建立另一份記事本。

| 項目 | 第一版建議 |
| --- | --- |
| 共編方式 | 同組多人可同時修改同一段文字，不需取得正式答案的編輯權 |
| 內容 | 以獨立段落承載純文字，每段單選所屬題目或全局，支援多行與複製貼上；顯示「想法／共識／待確認」提示文字，不自動寫入範本 |
| 題目篩選 | 上方功能列提供「全部」「全局」及可選題目；篩選只影響自己的畫面 |
| 段落歸屬 | 每段顯示歸屬標籤，可改為其他題目或全局；文字與歸屬均同步給同組 |
| 儲存 | 自動同步，顯示待同步、同步中、已同步、連線中斷、同步失敗 |
| 暫存意義 | 討論草稿用途；關閉記事本、切題、離開及重新加入都不自動清除 |
| 可見性 | 學員介面只顯示本組；第一版講師介面不提供閱讀及投影入口 |
| 正式答案 | 維持現有單人編輯與手動儲存；記事本不計入作答進度與完成狀態 |
| 帶入答案 | 提供「複製目前篩選內容」，由有答案編輯權的人貼入適當欄位 |
| 匯出 | 提供目前篩選內容或整本記事本下載 TXT，保留段落歸屬標籤；既有答案 JSON／CSV 不混入記事本，畫面須註明不包含 |
| 清空 | 「清空整本」放在更多選單，確認包含被篩選隱藏的所有段落及整組影響，保留完整快照供復原；第一版不提供一鍵清空篩選結果 |

第一版不包含圖片、附件、富文字、留言討論串、多本記事本或完整版本歷史。線上成員名單列為第一版功能；彩色遠端游標可留到第二版。

## 2. 學員操作

1. 加入小組後，在固定身分列旁顯示「小組記事本」；無題目或題目尚未開放時也可使用。
2. 桌面開啟右側面板，題目仍可閱讀；手機開啟全螢幕面板，保留清楚的返回按鈕。
3. 面板上方顯示組名、「同組共用・自動同步」、連線中的成員與同步狀態。開啟面板才計入記事本線上名單，同名成員分別以工作階段識別。
4. 上方選擇「全部」「全局」或特定題目，按「新增段落」記錄重點；每段的歸屬標籤可直接更改。
5. 輸入即在本機呈現，將文字變更短暫批次後傳送；正常網路下以其他成員約 1 秒內看見變更為驗收目標，需實測。
6. 收合面板不捨棄待同步內容；切題不重建共編文件，也不影響正式答案草稿。
7. 複製或下載討論內容後，答案編輯者自行整理、貼入與儲存答案。

建議畫面文字：

```text
第 2 組｜小組記事本                         收合
同組共用・自動同步              小明、小華在線上
篩選：［練習二 ▾］        ＋新增段落（歸屬：練習二）
已同步

［練習二 ▾］
先整理目前遇到的問題……

［練習二 ▾］
大家同意先確認使用情境……

複製目前篩選內容    下載 ▾    更多 ▾
討論紀錄不會自動成為正式答案。
```

面板必須支援鍵盤操作、焦點返回、手機鍵盤與捲動；同步狀態使用可供輔助工具讀取的狀態區，避免每個字都播報。

### 2.1 篩選與歸屬

| 目前篩選 | 顯示內容 | 新增段落的預設歸屬 |
| --- | --- | --- |
| 全部（首次開啟預設） | 全局及所有題目的段落，維持整本順序 | 全局 |
| 全局 | 僅全局段落 | 全局 |
| 某題目 | 僅該題目的段落，不混入全局 | 該題目 |

- 「全部」是檢視範圍，不是段落歸屬；「全局」代表不屬於任何單一題目。一段只能屬於一題或全局。
- 篩選是各使用者自己的檢視設定，不同步給組員，也不隨正式作答頁切題而自動切換；收合再開啟保留目前篩選，更換課程／小組回到全部。
- 編輯既有段落只修改文字，不依目前篩選重新指定歸屬。在「全部」中編輯練習二的段落，其歸屬仍為練習二。
- 歸屬標籤提供「全局」及可選題目；更改歸屬不改內容、不複製段落，也不改整本中的原有位置。
- 自己把段落改到目前篩選以外時，該段移出列表，顯示「已移至練習三」及「查看」入口。改為全局同理；全部檢視只更新標籤，不隱藏。
- 若他人更改正在編輯的段落歸屬，暫留該段並提示「已改為全局／其他題目」，待本機組字及該次編輯結束再移出，不能突然卸載輸入區或重新歸類本機文字。
- 題目選項沿用既有學員題目列的標籤範圍，包含尚未開放的題目；關題不限制討論記錄，記事本不額外顯示題目內容。沒有可選題目時仍可記錄全局段落。

### 2.2 段落邊界與新增規則

- 每段是有穩定 ID 的獨立文字區塊；畫面自動換行不算新段落。
- 「新增段落」在目前可見最後一段之後插入；若篩選結果為空，追加到整本末端。其他被隱藏的段落維持原有順序。
- Enter 拆出新段落；Shift+Enter 只在同段換行，不改歸屬。新段落的歸屬以建立當下的篩選為準：特定題目繼承該題，全部／全局預設全局；拆段後原段仍保留原歸屬。
- 在段落內貼上多行文字，預設保留為同段內換行，沿用該段歸屬；使用「新增段落」後貼上則沿用新段落歸屬，避免貼上內容意外改變已指定的題目。
- 新段落的 ID、文字與歸屬須在同一共編操作中建立；快速切換篩選不能把排隊中的新增操作歸到另一題。
- 第一版不以 Backspace／Delete 跨段合併，不提供跨段文字選取刪除或拖曳重排。刪除段落使用該段選單並確認；隱藏段落絕不可因相鄰可見段落的操作而被刪除。
- 篩選切換前完成目前中文組字並將變更交給本機共編文件；同步仍可在背景繼續，不可因只剩部分段落可見就回寫或取代整本文件。

## 3. 同時編輯與斷線

不能將整段文字在每次輸入時直接覆寫 Firebase：兩人同時輸入時會發生後存者蓋掉前者。既有答案的 revision 衝突阻擋也不能直接當成共編機制。

建議用 Yjs 的文字共編資料結構，透過新增的 Firebase 同步層傳遞增量變更。Yjs 文件說明增量更新可重複套用、可依不同順序接收；這提供合併基礎，但 Firebase 傳輸、可靠存檔及編輯器整合仍需自行實作與驗證。[官方更新 API](https://docs.yjs.dev/api/document-updates)

- 編輯器需具備經驗證的 Yjs 綁定；先以技術驗證選定相容版本，再固定依賴版本與載入方式。不要自行用整段 textarea 替換模擬共編。
- 歸屬是每段的一個共編欄位。兩人同時改同段歸屬時，由共編資料結構收斂為單一結果，不以裝置時間判定；畫面顯示實際結果，若本機選擇被遠端結果取代則提示，使用者可再次調整。文字編輯與歸屬修改互不覆蓋。
- 中文注音／倉頡輸入的組字過程不能被遠端更新打斷；游標、選取範圍及個人復原操作不能因同步跳動或撤銷他人輸入。
- 「已同步」必須代表目前本機待送更新全部獲得伺服器確認；Firebase 本機事件或本機持久化成功不能當作確認。
- 建議將共編文件及待送佇列保留在 IndexedDB，資料鍵包含課程、組別、文件世代；可評估官方 `y-indexeddb` 整合。[官方本機持久化說明](https://docs.yjs.dev/ecosystem/database-provider/y-indexeddb)
- 曾載入文件的裝置斷線後可繼續暫記，提示「僅保存在此裝置，尚未同步」。第一次載入失敗不可把空白當成既有內容；本機儲存失敗需明示並提供複製保留。
- 重連先確認課程、小組及文件世代仍有效，再同步待送更新；若已刪除、重置或清空，舊內容只供複製／下載，不得自動寫回。
- 使用者離開時若尚未同步，顯示提醒與複製出口；頁面強制關閉後的復原依賴本機持久化，不承諾無痕模式或清除瀏覽器資料後仍能救回。

## 4. 與現有程式的整合

已確認現況：`session.js` 訂閱整個 `courses/<CODE>`；`live.js` 訂閱整個 `live/<CODE>`；學員畫面會由 `student.js`／`ui.js` 重建。記事本不可放進這兩個高層訂閱，也不能跟著作答畫面每次重建。

建議獨立資料結構（相對於 `artifacts/interactiveWorkbook/public/data`）：

```text
notebooks/<CODE>/<gid>/
  meta: { schemaVersion, generation, state }
  generations/<generation>/
    updates/<operationId>: { payload, sessionId, createdAt }
  recovery/<snapshotId>: { payload, createdAt, reason }

notebookPresence/<CODE>/<gid>/<sessionId>:
  { name, lastSeen }
```

共編文件內部需由「整段長文字」調整為「有穩定 ID 的段落集合與順序」，以下為邏輯模型，實際共編型別由技術驗證選定：

```text
paragraphOrder: [paragraphId, ...]
paragraphs/<paragraphId>:
  text: 可共編文字
  scope: { qid: 題目穩定 ID 或 null, labelSnapshot: 最近一次可見的題目標籤 }
  deleted: 軟刪除標記
```

`qid: null` 代表全局。qid 及標籤快照作為單一歸屬值更新；題號／標題不可當識別鍵。篩選僅是共編文件的本機視圖，不刪除隱藏資料。歸屬更新、拆段與文字更新均以段落 ID 定位；刪段使用可復原的軟刪除，與遠端打字競爭時不得重建為可見段落，文字保留供救回。須驗證個人復原不會復原其他人的刪除或歸屬操作。第一版不清除仍可能收到離線變更的軟刪段落。

- `payload` 為共編更新的編碼資料；`operationId` 重試時沿用，避免同一操作反覆新增。
- 只訂閱本組目前世代的更新與本組在線名單；面板收合後可持續完成待送，離開課程則釋放所有監聽與計時器。
- 在線狀態使用每分頁／工作階段 ID，不使用共用裝置 ID 當唯一鍵；以斷線移除及過期判定清除離線名單。顯示名稱僅為自填姓名。
- 首次開啟以交易建立 metadata，避免兩台裝置各自初始化文件而互相覆寫。
- 更新採增量追加，不把完整文件每次覆寫；第一版不在多人編輯途中刪除／壓縮操作記錄。先量測單組長時間輸入的儲存量、重開載入時間，再制定總量門檻與安全壓縮方案。
- 清空時保存完整可復原快照並切換世代；舊世代更新由規則拒絕。新世代的建立與指向切換必須原子完成，不可先清資料再換指向。
- 快照復原是整組動作，需先保留目前版本再還原，並提示其他成員。並行清空需透過交易只允許一個預期世代成功。

## 5. 資料保留與管理操作

| 情境 | 建議行為 |
| --- | --- |
| 切換／關閉題目，清除本題答案 | 文字及段落歸屬保持原樣，關題不鎖住記事本 |
| 題目改名／重新排序 | 依穩定 qid 更新可見標籤，不改歸屬 |
| 題目封存或因修改複製出新題 | 原段落維持原 qid 並標記封存；不自動移到新題，成員可手動改歸屬 |
| 題目刪除或匯入題目後原 qid 消失 | 保留原 qid 與標籤快照，顯示「原題目已移除」；全部及該舊題目篩選仍能找到，提供改為其他題目／全局。舊題僅供檢視，禁止新增歸屬；篩選停在舊題時須先選新歸屬才能新增 |
| 小組改名 | 沿用 gid，內容保持，畫面更新組名 |
| 收合、離開及重新加入同組 | 重新載入既有內容；本機待同步資料依有效世代恢復 |
| 清空記事本 | 確認整組影響，保留最近一次清空前快照，原子切換世代 |
| 合併小組 | 暫停兩組記事本寫入，保留兩份同步內容，以來源組名分段組成新文件，保留每段的題目／全局歸屬並重新配置段落 ID，再完成組別合併；失敗可重試且不重複追加。舊裝置待送內容提供手動救回 |
| 刪除小組、重置課程、刪除課程 | 確認文案包含記事本與復原快照；先阻擋舊裝置寫入，再清除對應資料及在線狀態 |
| 匯入答案而取代組別 | 保留 gid 的組別保留記事本；移除的 gid 依刪組流程清理 |
| 課程代碼再次使用 | 不接受先前文件世代的離線更新，避免舊課程筆記混入新課程 |

跨節點管理操作需要可重試的狀態流程，不能只比照圖片「清理失敗即忽略」：共編中的舊裝置可能持續送出資料。合併前需凍結寫入並重新取得已確認更新；規則同步檢查 `state`、小組存在及世代。未成功同步的內容不保證自動納入合併，須有使用者救回入口。

## 6. 權限邊界

現有系統採匿名登入與課程代碼，角色及組別主要由前端控制。因此「介面只顯示本組」不代表資料庫已具備跨組隔離。第一版若沿用既有信任參與者模型，操作說明不能宣稱「只有本組有權讀取」。

若要求資料層真正限制本組共編、只有講師可以管理，需另增可信的身分／組別授權流程並配合資料庫規則；不能信任使用者自己提交的 gid 或角色。這是額外範圍，應於實作前確認是否需要。

## 7. 實作順序與驗收

1. 先做同步技術驗證：兩台裝置編輯同段、中文輸入、游標穩定、斷線重連與伺服器確認狀態。未通過不進入正式畫面整合。
2. 完成段落模型、題目篩選、歸屬修改、獨立資料節點與面板，確認無題目／未開放題目也可使用，以及答案編輯鎖完全獨立。
3. 完成本機保留、清空復原、小組合併／刪除／重置流程與規則，接上操作說明。
4. 多裝置與手機驗收後部署資料庫規則及新版介面；舊課程按首次使用建立記事本，不批次改寫既有答案。

核心驗收情境：

- 篩選練習二新增段落後，該段自動歸屬練習二；另一位組員在全部檢視看得到，在練習一看不到。兩人選不同篩選時互不影響。
- 全部與全局篩選下新增段落歸屬全局；修改既有段落文字不更動歸屬。Enter、Shift+Enter、多行貼上及快速切換篩選符合既定規則。
- 將段落從練習二改成練習三或全局，只變歸屬且內容完整；目前篩選正確移出並提示，目標篩選可找到原段落。
- 他人改歸屬時本機正在中文組字，不中斷輸入且最終文字與歸屬一致；兩人同時改歸屬、另一人同時輸入，所有裝置最終收斂。
- 篩選狀態的新增、刪除、複製及下載不誤操作隱藏段落；清空整本明確涵蓋隱藏內容，復原後恢復文字、順序及歸屬。
- 題目改名、重新排序、封存、刪除與匯入取代後，筆記仍能找到且不誤歸到同題號的新題；清空復原及合併保留各段歸屬。

- 同組至少三台裝置同時輸入、同位置插入／刪除／貼上後，所有裝置收斂至相同內容，未因整段覆寫遺失他人的獨立輸入。
- 沒有正式答案編輯權的人仍可共編；記事本輸入不取得／續期答案編輯鎖，不改動答案草稿、revision、完成狀態或投影。
- 中文組字期間收到遠端修改、另一人儲存答案、講師關題／改題時，文字、游標與面板狀態維持正確。
- 不同組在正常介面各自讀寫各自記事本；若採可信授權方案，另驗證跨組直接請求會被規則拒絕。
- 斷線輸入後重新整理可恢復本機資料，重連完成同步；同步拒絕時不可顯示已同步。
- 斷線期間發生清空、刪組、重置、合併，重連不得把舊內容寫回，但使用者仍可複製救回本機文字。
- 清空與同時輸入、雙人同時清空、清空後復原及合併重試，皆不造成無提示資料遺失或重複內容。
- 離開再加入／更正組別後，沒有舊 listener、舊名單或文字串到新組；快取與新版規則錯配時明確提示更新。
- 手機直向及軟鍵盤開啟時，可輸入、捲動與返回；長時間討論的首次載入、更新延遲與資料量符合實測訂定的上限。
