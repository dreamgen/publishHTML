# 互動題本｜架構與模組規約

下一版功能（見 `功能規劃-下一版.md`）的實作契約。任何人／任何子代理改這個資料夾之前先讀這份，
它決定了模組邊界、資料模型與跨模組介面，避免各功能各自長出一套做法。

---

## 一、檔案結構

```
interactiveWorkbook/
  index.html            頁面骨架（不含樣式，只留 <link> 與開機看門狗）
  styles/
    base.css            原本內嵌的全部樣式（重構時原封搬過來）
    group.css           功能一：小組管理
    editlock.css        組內編輯鎖
    projection.css      功能三：投影
    editor.css          功能二：題目編輯器
  app.js                進入點，只做 boot / enterApp / 組裝
  modules/
    firebase.js         Firebase 初始化、authReady、courseRef、liveRef
    util.js             E、notify、pad、toArr、randomCode、randomId、derivePassword、exLabel…
    storage.js          localStorage / sessionStorage / deviceId
    schema.js           欄位型別、上限、TEMPLATE、validate*、名稱正規化
    data.js             資料層：normalizeCourse（含遷移）、建課、加入、存答案、題目 CRUD
    state.js            共用可變狀態（單一匯出物件 S）
    ui.js               shell、tabs、notify 容器、dialog／展開視窗、截斷
    render.js           rerender() 派發（依角色呼叫 renderStudent / renderTeacher）
    session.js          startSession / applySnapshot / leaveSession
    entry.js            學員／講師入口畫面、建立課程完成畫面
    student.js          學員作答畫面、欄位渲染、存檔
    teacher.js          講師控制台
    live.js             live/<CODE> 的獨立訂閱（活動標記 + 編輯鎖資料），已完成
    editlock.js         組內編輯鎖的取得／釋放／接手邏輯與畫面
    projection.js       狀態點與四個投影模式
    editor.js           題目編輯器與封存／還原
  sw.js                 快取策略（動態快取，新增檔案不必改清單，只需 bump SW_VERSION）
  database.rules.json
```

`sw.js` 用 stale-while-revalidate 動態快取，**新增模組檔案不需要改 sw.js 的清單**，但改版時要 bump `SW_VERSION`，
否則使用者拿到的是舊快取。

## 二、模組規則

1. ES modules，`index.html` 只有 `<script type="module" src="./app.js">` 一個入口。
2. **共用狀態集中在 `state.js`**，匯出單一物件：

```js
export const S = {
  session: null,    // {role, code, gid, author, courseName}
  course: null,     // normalizeCourse() 的結果
  unwatch: null, unwatchLive: null,
  qid: null,        // 目前題目的穩定 ID（取代舊的 ex 索引）
  draft: {}, dirty: false, revision: 0,
  groupFilter: 'all', projection: false, busy: false, joinOpen: false,
  projMode: 'dots', projScale: 1, projField: null, projGroups: [],
  live: { activity: {}, editLocks: {} },
  lastStudentSignature: '',
};
```
   ES modules 的 import 是唯讀繫結，**不可以** `import { qid }` 再賦值；一律 `S.qid = …`。

3. **循環 import 允許，但只能在函式體內使用被匯入的東西**，不得在模組頂層執行期就呼叫（會拿到 undefined）。
   需要重畫時 `import { rerender } from './render.js'` 並在事件處理函式裡呼叫。
4. 每個功能只改自己的 CSS 檔，不要動 `styles/base.css`，也不要回頭在 index.html 內嵌樣式。
5. 所有寫入資料庫的函式集中在 `data.js`／`editlock.js`，畫面模組不直接呼叫 `set`／`update`。
6. 使用者可見文字一律繁體中文，語氣與既有訊息一致（完整句、講清楚後果）。

## 三、資料模型 v2

### 3.1 主節點（會被主監聽 onValue 完整訂閱）

```
artifacts/interactiveWorkbook/public/data/courses/<CODE>/
  name, pwSalt, pwHash, pwIter, createdAt
  schemaVersion: 2
  exercisesJson: "<JSON 陣列字串>"     # 題目全文，含已封存題
  allowStudentGroupNames: true|false  # 功能一：是否允許學員自訂組名
  locks:    { <qid>: true|false }      # true = 未開放
  groups/<gid>/
    name, nameKey, author, createdAt
    answers:  { <qid>: "<answer JSON>" }
    complete: { <qid>: bool }
    updated:  { <qid>: ts }
    revision: { <qid>: n }
```

`exercisesJson` 解析後每一題：

```js
{
  qid: "3f2a91c7",          // 穩定 ID，randomId(8) 的十六進位字串，永不重複使用
  rev: 0,                   // 題目本身的 revision，講師編輯用樂觀鎖
  status: "active",         // "active" | "archived"
  archiveReason: "edit",    // 只有 "edit"（因修改而封存）；其他情況不設
  replacedBy: "<qid>",      // 封存題 → 取代它的新題
  archivedFrom: "<qid>",    // 新題 → 它是從哪一題複製出來的
  restoredNote: true,       // 曾被還原，標題要加註記
  title, time, goal, notice, reference, fields   // 與舊版相同
}
```

- **順序＝陣列順序。** 沒有另外的 order 節點。
- **封存題留在同一個陣列裡**，由 `status` 過濾。畫面上的「練習一／二／三」只數 `status === 'active'` 的題，
  所以封存不會在題號上留洞。
- RTDB 的 key 不能含 `. $ # [ ] /`；`randomId()` 產生十六進位字串，安全。

### 3.2 易變節點（**不可**放在 courses 底下）

活動標記與編輯鎖每幾秒就會變動；若放在 `courses/<CODE>` 之下，主監聽會被它們不斷觸發整頁重畫，
規劃文件明確要求「只更新點、不觸發主畫面重繪」。因此放在同層的獨立子樹，用**獨立的 onValue**：

```
artifacts/interactiveWorkbook/public/data/live/<CODE>/
  activity/<gid>/<qid>/<fieldKey>: true        # 橘點：已被點過
  editLocks/<gid>: { holder, name, lastActive } # 組內編輯鎖
```

- `database.rules.json` 要補 `live/$code` 的規則（與 courses 同樣 `auth != null`）。
- 刪除課程、重置課程、刪除小組時，要一併清掉對應的 `live/<CODE>`（或其中該組的部分），
  不能留孤兒資料。
- `holder` 是裝置 ID（`storage.js` 的 `deviceId()`，存在 localStorage，鍵 `iw_deviceId`），
  `name` 是該裝置加入時填的姓名（顯示用），`lastActive` 是毫秒時間戳。

### 3.3 舊資料相容與遷移（**這是最容易出錯的一段**）

舊資料（無 `schemaVersion`）的答案是用題號索引當 key。相容規則：

1. **讀取端做決定性補號，不需要先寫入。** `normalizeCourse` 解析 `exercisesJson` 時，
   任何沒有 `qid` 的題目，依它在陣列中的索引 `i` 指定 `qid = "L" + i`。
   決定性表示所有裝置（講師與學員）在遷移前就會算出同一組 qid，不會彼此打架。
2. **查答案時雙軌 fallback**：`answers[qid] ?? answers[legacyIndex]`（legacyIndex 只在 qid 形如 `L<i>` 時成立）。
   `complete` / `updated` / `revision` / `locks` 同理。
3. **一次性遷移由講師端觸發**：講師控制台載入時若 `schemaVersion !== 2`，執行一次遷移
   （寫入帶 qid 的 `exercisesJson`、把 locks 與各組 answers/complete/updated/revision 從索引改成 `L<i>` 為 key、
   刪掉舊的數字 key、寫 `schemaVersion: 2`）。用 `runTransaction` 在整個課程節點上做，避免兩台講師裝置同時遷移。
   遷移必須是**幂等**的：重跑一次不會壞。
4. 遷移前的學員端也能正常作答（靠第 1、2 點）。遷移後學員端會收到 snapshot 自然接上。
5. 匯出的 JSON 仍以 `titles` + 每組答案輸出，**匯出格式額外帶 `qid`**，但匯入時以組名對應、
   答案以 qid 對應（找不到 qid 時退回用題號位置），保持舊備份檔仍可匯入。

## 四、跨模組介面（各功能實作時遵守）

`data.js` 需要匯出（名稱固定，其他模組照這個呼叫）：

```js
normalizeCourse(raw)                 // → { name, createdAt, schemaVersion, allowStudentGroupNames,
                                     //     exercises: [...active], archived: [...archived],
                                     //     byQid: {qid: exercise}, locks: {qid:bool}, groups: {gid:{…}} }
activeExercises(course)              // status==='active' 的題目陣列（＝course.exercises）
exerciseIndex(course, qid)           // 在 active 陣列中的位置，用於「練習一」的題號
fetchCourse(code) / createCourse(name, password) / verifyTeacher(code, password)
migrateCourseIfNeeded(code)          // 3.3 的一次性遷移
listGroups(code)                     // 入口畫面用
createGroups(code, names[])          // 講師預先命名
renameGroup(code, gid, name)
mergeGroups(code, keepGid, dropGid, perQuestionChoice)
deleteGroup(code, gid)               // 含清掉 live/<CODE>/*/gid
joinGroup(code, {gid | name}, author)// gid → 加入現有組；name → 新增組（正規化後再比對一次）
saveAnswer(code, gid, qid, answerObject, expectedRevision, complete, author)
setLock(code, qid, locked)
deleteExercise(code, course, qid)    // 真刪除，含各組該題答案與 live 資料
saveExercise(code, course, exDef, expectedRev)   // 樂觀鎖；rev 不合就丟錯
archiveForEdit(code, course, qid)    // → 新題 qid（封存原題、複製出新題）
cancelEdit(code, course, newQid)     // 解除封存、刪掉新題，等同沒發生
restoreExercise(code, course, qid)   // 還原封存題，預設關閉、標題加註記
```

`ui.js`：

```js
shell(body, options)                 // 沿用現有行為
tabs() / bindTabs()                  // 題目切換（以 qid 為 data 屬性，不再用索引）
expandDialog(title, text)            // 截斷文字的展開浮動視窗（投影與封存答案共用）
truncate(text, max)                  // 回傳 {shown, truncated}
confirmDialog(message)               // 需要的話；不要在同一個動作裡連續彈兩個 confirm
```

`live.js`（**已實作**，編輯鎖與投影共用，不要重寫）：

```js
watchLive(code) / stopWatchLive()    // live/<CODE> 的獨立訂閱，寫入 S.live
onLiveChange(fn)                     // 登記訂閱者，回傳取消函式；回呼裡只做局部更新，不要 rerender()
hasActivity(gid, qid, fieldKey)      // 橘點判斷
markActivity(code, gid, qid, fieldKey)      // 寫橘點；同欄位只寫一次
clearActivityForQuestion(code, qid)  // 講師清除本題答案時一併清掉
```
`startSession` / `leaveSession` 已經接好 `watchLive` / `stopWatchLive`，不必再處理訂閱生命週期。

`editlock.js`：

```js
myEditLock(gid)                      // → {mine:bool, holderName, idleMs, canTakeover:bool}
acquireLock(code, gid) / releaseLock(code, gid) / takeoverLock(code, gid)
touchLock(code, gid)                 // 有動作就歸零，節流：最多每 20 秒寫一次
```

## 五、不變條件（review 時逐條檢查）

1. **答案不會無聲消失。** 只有「刪除題目」「刪除小組」「重置」「刪除課程」會讓資料消失，且都要先確認。
   任何新機制不得製造第二條無聲路徑。
2. **樂觀鎖不能被繞過。** 答案沿用 revision 比對；題目用 `rev` 比對。任何新的寫入路徑都要帶比對。
3. **投影字數**：1920×1080、28px 以上、每組 150～200 字就滿版。截斷是必要條件，不是美化。
4. **狀態點只做局部更新**：每顆點固定 id，更新只改 class，不重畫頁面、不位移、不跳捲動位置。
5. **主監聽不得被易變資料觸發**：活動標記與編輯鎖只能在 `live/<CODE>`。
6. **有社交管道的地方不做系統防護**：組內衝突交給人，講師單方面改題才需要系統補保護。
7. 學員在未開放／唯讀狀態下，未儲存內容不得被畫面重繪清掉（沿用現有 dirty 保護邏輯）。
8. 匯出 CSV 的公式注入防護（`'` 前綴）與 BOM 不能弄丟。
