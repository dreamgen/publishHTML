# PureReader 網頁解析方案分析報告

日期：2026-07-09
案例網址：https://look.twword.com/030346010/8001_312.html

## 一、現行架構

`extractArticle()`（index.html 約 L1787）依序嘗試四個 CORS 代理，取得 HTML 後以 Mozilla Readability 萃取正文：

| 順序 | 策略 | 端點 |
|---|---|---|
| 1 | PureReader Proxy | `purereader-proxy.vercel.app/api/proxy` |
| 2 | CodeTabs | `api.codetabs.com/v1/proxy` |
| 3 | AllOrigins JSON | `api.allorigins.win/get` |
| 4 | AllOrigins Raw | `api.allorigins.win/raw` |

輔助機制：hostname 策略偏好（記住上次成功策略）、快取優先、JS redirect 偵測、Cloudflare bot 頁偵測、背景下載 fallback。

NovelMode 預載另有一份重複的 `_fetchHtml()`（約 L3307），只用前三個策略。

## 二、實測結果（2026-07-09）

| 管道 | 結果 |
|---|---|
| 直接抓取 | ❌ 空回應（Cloudflare 擋非瀏覽器/資料中心請求）|
| PureReader Proxy (Vercel) | ❌ 空回應（Vercel 出口 IP 被 Cloudflare 擋）|
| CodeTabs | ❌ 失敗 |
| **AllOrigins JSON (`/get`)** | ✅ **成功，回傳完整章節內容**（http_code 200，18946 bytes）|
| AllOrigins Raw (`/raw`) | ❌ 空回應 |
| **Jina Reader (`r.jina.ai/<url>`)** | ✅ **成功，直接回傳乾淨正文 markdown** |

結論：**網站並未擋死所有管道**，AllOrigins JSON 與 Jina Reader 均可正常取得內容。

## 三、根本原因

### 1. Bot 偵測短路 bug（主因）

`extractArticle()` 的成功判定只有 `content.length > 500`，而 Cloudflare 偵測
（`isBotProtected`）放在策略迴圈**之後**：

```
for (strategy of strategies) { ... 長度>500 即 break ... }
if (isBotProtected) throw ...   // ← 在迴圈外，直接終止
```

Cloudflare challenge 頁（"Just a moment..."）長度遠超過 500，因此只要排序在前的
CodeTabs / Vercel proxy 收到 challenge 頁，就會被當成「成功取得」，接著觸發 bot
偵測直接 throw —— **後面的 AllOrigins JSON 根本沒有機會執行**。

此站「近日才變成無法取得」的原因即是：Cloudflare 開始對 CodeTabs / Vercel 的
出口 IP 回應 challenge 頁（先前可能是直接放行或回錯誤，錯誤會正常 fallback）。

策略偏好機制會加重此問題：若某 hostname 曾記住 winner 為策略一/二，該策略回傳
challenge 頁後仍會「贏」，並持續覆寫偏好。

### 2. 成功判定太寬鬆

`length > 500` 無法區分正文、challenge 頁、錯誤頁、軟 404。

### 3. NovelMode `_fetchHtml()` 重複且更弱

門檻僅 `length > 200`、完全沒有 bot 頁偵測，預載時可能把 challenge 頁
當成章節存入 IndexedDB 快取，之後即使網站恢復也讀到髒資料。

## 四、建議改法

### A. 把驗證移入策略迴圈（最小修正，立即恢復此站）

新增共用驗證函式，challenge 頁視為「該策略失敗」，繼續 fallback：

```js
function isBotChallengePage(html) {
    return html.includes('cf-browser-verification')
        || html.includes('Just a moment...')
        || html.includes('Checking if the site connection is secure')
        || (html.includes('Cloudflare') && html.includes('Ray ID'))
        || html.includes('_cf_chl_opt');           // challenge 頁專屬變數
}

function isUsableHtml(html) {
    if (!html || html.length < 500) return false;
    if (isBotChallengePage(html)) return false;
    return true;
}

// 迴圈內改為：
const content = await strategy.fn();
if (isUsableHtml(content)) { htmlContent = content; winnerIdx = strategy.idx; break; }
if (content && isBotChallengePage(content)) {
    lastError = 'Cloudflare 真人驗證';
    continue;   // ← 關鍵：換下一個代理，而不是放棄
}
```

注意：正常頁面也可能載入 `cloudflareinsights` beacon 或
`challenge-platform/.../jsd/main.js`（本案例頁面就有），**不可**把這兩者列入
challenge 判定，否則會誤殺正常內容。`_cf_chl_opt`、`cf_chl_` 才是
challenge 頁專屬特徵。

全部策略都失敗且至少一個回傳 challenge 頁時，才顯示「網站防火牆阻擋」訊息。

### B. 新增策略五：Jina Reader（最終防線）

```js
{ idx: 4, label: 'Jina Reader', fn: async () => {
    const res = await fetch(`https://r.jina.ai/${url}`, {
        headers: { 'X-Return-Format': 'html' },   // 要求回傳渲染後 HTML，可續用 Readability
        signal: currentFetchAbort?.signal
    });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.text();
}}
```

優點：Jina 以真實無頭瀏覽器渲染，能通過多數 Cloudflare 檢查、支援 JS 渲染頁。
限制：免費層有速率限制（無金鑰約 20 req/min/IP），適合當備援而非首選；
若 `X-Return-Format: html` 因 CORS preflight 出問題，可改接受預設 markdown
並以簡單轉換（空行切段落包 `<p>`）繞過 Readability 直接渲染。

### C. 統一抓取邏輯

把策略清單與驗證抽成單一 `fetchViaProxies(url, signal)`，
`extractArticle` 與 NovelMode `_fetchHtml` 共用，並讓 `_fetchHtml`
同樣獲得 bot 頁偵測（避免污染預載快取）。

### D. 中長期：強化自有代理（原始碼在 purereader-proxy 專案，不在本 repo）

1. **改部署 Cloudflare Workers**：出口為 Cloudflare 自家網路，被目標站
   （多數也用 Cloudflare）擋的機率遠低於 Vercel/AWS IP；免費額度 10 萬次/日。
2. **送出真實瀏覽器 headers**：`User-Agent`（真實 Chrome UA）、`Accept`、
   `Accept-Language: zh-TW`、`Referer`（帶目標站首頁）、`sec-ch-ua` 系列。
   許多站只擋「無 UA / 預設 fetch UA」的請求。
3. **快取**：Workers Cache API 對同 URL 短時間快取，減少對目標站的請求頻率，
   降低被封鎖機率。
4. 若要處理最頑固的站，可在 proxy 端整合渲染服務（如 Cloudflare Browser
   Rendering），但成本較高，建議僅作深度解析（`/api/deep`）的後盾。

### 其他小建議

- 策略偏好 `saveStratPref` 應只在通過 `isUsableHtml` 驗證後寫入。
- `queueForBackground` 的 Background Fetch 也固定用 AllOrigins `/get`，
  可沿用同一策略清單。
- 失敗訊息可區分「所有代理均失敗」與「代理可達但被防火牆擋」，
  幫助使用者判斷是否要用「分享網址」開瀏覽器。

## 五、優先順序

2. **B**：低成本大幅提升抗阻擋能力。
3. **C**：消除重複邏輯與快取污染風險。
4. **D**：中長期基礎建設。
