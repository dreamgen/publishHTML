## 二、額外調整的原因

1. **測試期綁定開關設計雙軌保留（`autoApproveBind` ＋ UI 切換鈕）**：
   - 【已變更】本點的 `localStorage` 覆蓋開關已在 Code Review 階段 1 移除，改由資料庫 `td116/config/autoApproveBind`（只有總召可寫）決定，見第五節。
   - **原因**：需求要求「測試期間，立即生效，完工後恢復」。若只在程式碼寫死立即生效，後續審核與回歸測試時很難在不改程式碼的情況下驗證「待區長確認」流程。
   - **調整做法**：在 `config.js` 定義 `autoApproveBind: true`（完工恢復時只需改為 `false`），同時在 `M8` 綁定畫面提供 `localStorage` 覆蓋開關，且於 `B5` 分工與送出頁面實作了待審核綁定的同意／退回介面，確保「立即生效」與「完工後審核」兩條路徑皆可完整測試。
2. **修訂 `D10` 等預設提案所對應的真實 `slot.id`**：
   - **原因**：比對 `data.js` 後發現 12/11 冬季大典前晚在 `BASE_DATA.slots` 的實際 ID 為 `S187`（而非早先估算的編號）；2/27 內湖同日衝突為 `S007` 與 `S180`；3/21 交通為 `S200` 與 `S201`。
   - **調整做法**：改以實測驗證後的真實 `slot.id` 綁定於 `buildInitialProposals()`，使 `D10` 方案甲試算時能真實消除 `A2` 明德班日違規。
3. **手機與桌機排版由螢幕尺寸驅動，移除路由條件寬度切換（取代原 `.wide-app`）**：
   - **原因**：階段一、二曾以 `.wide-app` 依路由切換 `720px`／`1392px` 寬度及 `.top`／`wsHeader` 雙軌頁首，但使用者反饋切換功能時版面寬度與頁首會產生跳動感。

## 七、v17 修正（2026-11-18）

依 v16 審閱結果與使用者決定修正，版號 v17（`sw.js`、`index.html`）。

1. **新增名冊人員規則（使用者確認）**：排班人員新增名冊人員**不需確認（不限區）**，保留 v15 規則行為。排入時仍依預排規則：「新增並加入」與批次加入都依 `isPreFor(area)` 標 `pre: true`，只有該區區長能確認；已有測試涵蓋總召替六區新增並排入的情形。
2. **規則產生器同步**：開發用規則產生器已加入 v15 的 `addedPeople` 條件，產生結果與 `database.rules.json` 的 JSON 內容完全一致；規則檔本身沒有變動。
3. **找人提示跳脫**：整頁重繪時 `#finderHint` 一律 `esc()`（局部更新本來就是 `textContent`）；新增的批次說明區也逐項 `esc()`。
4. **B3 收合狀態**：收合記憶改用穩定的區段代號（`data-sec`：`groups`／`jz`／`oth`／`ym-月份`），不再比對含動態數字的摘要文字；資料變動重繪後維持使用者的收合狀態，焦點還原鍵（`ctlKey`）也改用區段代號。
5. **批次加入**：多人批次必須與名冊姓名完全相符且唯一才加入；部分相符、同名多人（不論同區或不同區）、找不到、不在該區者都不加入，列在提示下方並說明原因（例如「部分相符：陳明德、陳明華」「找不到」），並留在搜尋框。完全相符但有違規者仍可加入（既定規則：可排入但標違規），按鈕、紀錄與提示標示違規人數。批次帶 undo、`touchArea`、依 `isPreFor` 標預排；單次上限 100 人。單一姓名搜尋不變。
6. 順帶：換路由時關閉「選擇去年合作組合」抽屜（`UI.lyPick`）。
7. **測試更新**：`app-test` 的 PERM-3 改為比較呼叫前後資料不變、FILL-5／FILL-6 改為驗證帶入名單等於 115 年該隊名單；`phase4-test` 的版號斷言改為讀取目前 `sw.js` 版號；`v16-test` 的批次斷言配合第 5 點調整；新增 `v17-test`。

1. **共用算法 `E.areaLoad(M, {filter})`**（engine.js）：各區各類次數（廚務含會館輪廚、服／整、禮節、洗碗、忠恕平／六／日、前晚協辦、交通）、假日次、平日次、請假天、需求人次、已排人次、可排人數、人均需求、負擔比。次數依 `share`（聯合勤務各 0.5）；需求人次直接用各格 `need`（聯合格已各自分配人數，不再乘 share）。人均需求＝需求人次÷該區可排人數（不含不再排班）；負擔比＝人均需求÷六區平均。另有 `E.areaLoadShift(L, s, M, to)` 不重建模型、直接推算單一格改派後兩區的變化。數字已與舊排班主控台「各區負擔統計」逐欄核對一致。
