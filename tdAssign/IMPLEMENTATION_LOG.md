## 二、額外調整的原因

1. **測試期綁定開關設計雙軌保留（`autoApproveBind` ＋ UI 切換鈕）**：
   - **原因**：需求要求「測試期間，立即生效，完工後恢復」。若只在程式碼寫死立即生效，後續審核與回歸測試時很難在不改程式碼的情況下驗證「待區長確認」流程。
   - **調整做法**：在 `config.js` 定義 `autoApproveBind: true`（完工恢復時只需改為 `false`），同時在 `M8` 綁定畫面提供 `localStorage` 覆蓋開關，且於 `B5` 分工與送出頁面實作了待審核綁定的同意／退回介面，確保「立即生效」與「完工後審核」兩條路徑皆可完整測試。
2. **修訂 `D10` 等預設提案所對應的真實 `slot.id`**：
   - **原因**：比對 `data.js` 後發現 12/11 冬季大典前晚在 `BASE_DATA.slots` 的實際 ID 為 `S187`（而非早先估算的編號）；2/27 內湖同日衝突為 `S007` 與 `S180`；3/21 交通為 `S200` 與 `S201`。
   - **調整做法**：改以實測驗證後的真實 `slot.id` 綁定於 `buildInitialProposals()`，使 `D10` 方案甲試算時能真實消除 `A2` 明德班日違規。
3. **手機單手頁面（`B3–B6`）與桌機寬版工作台（`A6/B1/B2`）共生排版**：
   - **原因**：原 `tdAssign` 的 `#app` 鎖定 `max-width: 720px`，若直接套用於 `A6` 進度表、`B1` 區長雙欄首頁及 `B2` 多方案並排比較表，表格欄位會過度擠壓。
   - **調整做法**：在 `styles.css` 新增 `.wide-app`（`max-width: 1392px`）與響應式雙欄 `.split-grid`，依路由自動切換容器寬度，保留手機端操作流暢度的同時完整還原設計稿桌機雙欄體驗。
4. **`input` 事件焦點保護、IME 倉頡組字不中斷與局部 DOM 更新**：
   - **原因**：原 `app.js` 監聽所有 `data-input` 並在每次按鍵時執行整頁 `render()` 重寫 `#app.innerHTML`，導致使用倉頡／注音等中文輸入法時，組字碼在 `compositionstart`～`compositionend` 期間因 `<input>` DOM 節點被銷毀重建與重設游標而被強行切斷；背景同步或切換時的整頁重繪也可能打斷正在輸入的文字框。
   - **調整做法**：
     1. 實作 `compositionstart` / `compositionend` 與 `ev.isComposing` 防護：組字期間略過 `input` 過濾並延遲背景 `render()`（設 `pendingRender`），待組字完成再更新。
     2. 搜尋輸入改為 `updateSearchDom(k)` 局部更新結果容器（`#cands`/`#finderHint`、`#appt`、`#bindHits`、`#famHits`），完全不重建 `<input>` 元素本身。
     3. 背景 `render()` 重繪前保存同路由非搜尋表單控制項的 `.value` 與游標選取範圍，重繪後還原，確保任何文字框都不會被同步重繪清空。

## 三、自行補充的假設（供 Review 核實）

1. **禮節隊「帶入去年」與「6 大崗位」資料來源假設**：
   - `BASE_DATA.defaultGroups` 中所有禮節隊（`lj_*`）目前皆為空陣列 `[]`。
   - 系統假設：當使用者在禮節隊按「帶入去年」且 `defaultGroups` 為空時，比照 `tdSchedule` 的邏輯，從該區具備 `p.li`（115 年禮節經驗）且非主廚／大廚的人員中篩選，若分 1／2 隊則依序交錯均分帶入；6 大崗位預設定義為 `['操持', '燒香禮', '請壇禮', '辦道禮', '獻供人員', '填表／掛號']`，並可依 `p.li` 字串比對自動推薦配崗，儲存於 `td116/groupMeta/{gk}/posts`。
2. **無組別勤務（`B4`）「帶入去年名單」篩選假設**：
   - `BASE_DATA` 未包含 115 年逐日無組別（忠恕輪值、大典前晚等）的歷史逐筆名單，僅於人員物件上帶有 `p.zr`（忠恕角色）與 `p.n115`（115 年服務次數）。
   - 系統假設：按「帶入去年名單」時，以本區在 115 年具 `p.zr` 忠恕角色或 `p.n115 > 0` 且當天無硬違規的人員依經驗排序補入至多到該格需求人數。
3. **跨區協調與 `acks` 例外處理的範圍假設**：
   - `TDEngine` 本身為純規則計算模組，不主動濾除例外紀錄。
   - 系統假設：將 `acks/{issueKey}` 的 `st === '接受例外'` 處理放在 `tdAssign/app.js` 的 `recompute()` 與 `cnt()` 層，使「接受例外」能即時讓各區與總召儀表板的違規／碰撞計數下降，但仍可在 `A6` 折疊區檢視與撤銷，維持引擎核心 `engine.js` 規則判斷邏輯不變。
4. **提案 `D10` 方案丙之試算模擬假設**：
   - 設計稿 `B2` 提到丙方案為「瑞芳與基隆＋新莊互換秋冬」，但未指定秋季對應之確切單一日期。
   - 系統假設：以 `BASE_DATA.slots` 中的秋季大典前晚（10/13 `S185` 基隆、`S186` 新莊）與冬季大典前晚（12/11 `S187` 瑞芳）作為方案丙的具體模擬對調標的，並由 `TDEngine` 如實算出對調後的違規與場次差異。
5. **區長提名（`B1`）資料格式假設**：
   - 設計稿 `B1` 顯示小組長與儲備廚師提名功能但未定義資料庫結構。
   - 系統假設：存於 `td116/nominations/{area}`（含 `leads` 字串、`cooks` 字串、`updatedBy`、`updatedAt`），以文字輸入搭配本區資深可帶隊名單提示的方式讓區長快速填報。
6. **未綁定或未設定姓名之人格預設區域（`defaultArea`）**：
   - 設計稿中「總覽 → 本區首頁／提案」需要知道目前預設查看哪一區。
   - 系統假設：依序優先取「當前使用者負責的六區之一」→「`M8` 綁定人員的所屬區」→ 預設 `'瑞芳'`（使用者可在 `B1` 右上角隨時切換其他區）。
